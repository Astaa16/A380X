A380X XP12 development build

This is an independent, non-commercial conversion from the pinned FlyByWire A380X source. It contains an early X-Plane aerodynamic model and converted exterior, passenger cabin with seats, and 3-D cockpit OBJ assets. It is not a validated simulation of the real A380; the first FBW-derived display and state-machine slice is included, but the complete avionics stack is not yet ported.

Use the 3-D cockpit command-look view; check Keyboard settings for its assigned shortcut. The physical FCU retains its authored panel and legends, with live selected speed, heading, altitude, and vertical-speed values in its four display windows driven by transitional X-Plane autopilot datarefs. Both pilot-side PFD and ND pairs are drawn by the aircraft-local A380X FBW Avionics plugin. It ports the pinned FlyByWire FMA priority and flight-phase primitives and consumes only raw sensor, engine, electrical and failure inputs at the simulator boundary; it does not consume X-Plane EFIS, moving-map, flight-director, VNAV or autopilot mode status. The NDs intentionally show a partial compass/track presentation until the FBW FMGC, FMS and navigation database are ported. Both MFDs are X-Plane 12.1+ plugin cockpit devices drawn and touched through the same plugin, and both KCCUs (keys, scroll wheel, cursor-select button, trackball pop-up and KBD/CCD switches) send aircraft-local commands to the MFD on their own side; the SD and the other system screens stay powered-off geometry. Two hundred ninety-two configured FCU, EFIS, DU, glare-shield, overhead, pedestal, KCCU, throttle-quadrant, and passenger-door controls plus 34 flyPad touch regions have native-command, command-knob, toggle, or drag-axis development targets and labeled mouse tooltips; the remaining controls are not interactive. The passenger seats and suites are static geometry, and their seatback screens are static powered-off faces. The transparent custom panel removes X-Plane's generic 2-D artwork. The former native-EFIS FlyWithLua display window is not packaged. The same native plugin draws a shared, touch-enabled flyPad surface onto both authored tablets. It uses the pinned MSFS flyPad theme, status bar, icon toolbar, page tabs, and card-based Dashboard layout, and preserves the FlyByWire page model, A380 limits, cabin/checklist data, tablet battery timing and TOD formulas while adapting payload, fuel, ground services, radios, failures and presets to native X-Plane datarefs and commands. The former Lua EFB is no longer packaged because its command namespace would conflict.

Development warning: structural validation is not visual or flight acceptance. The October 4 horizontal-tail correction passed offline placement checks. A short native X-Plane check confirms tail placement and rightward cockpit view movement. The tail-v3 update corrects one-based skin joint indices and moves all four complete elevator panels using the pilot pitch input as a visual fallback. Trim follows the actual stabilizer-degree output with source-calibrated angles and a positive-leading-edge-up convention. Offline movement, seam, and neutral-geometry checks pass; native animation acceptance and independent FBW actuator behavior remain unverified.

The subsequent model update restores six FBW cockpit wall/window/sideboard materials and gives rigid and blended wing pieces a common neutral skin pose. These updates passed offline geometry, texture and preview checks but await a native recheck. The later flap/aileron update corrects the optimized wing joint palette and moves all six main flap panels as complete rigid skins. Exported flap geometry stays within 32 mm of the source at all 41 authored poses; this is an approximation, not exact skinning. Roll direction and neutral return were checked offline. The spoiler update moves all sixteen panel skins, restores five left linkage animations and uses eight native speedbrake/combined-roll channels with clamped travel. Exported spoiler motion stays within 14 mm of sampled source poses. It is a shared-channel approximation: exact FBW flap-dependent spoiler scheduling and ground-deployment logic are not implemented. Native animation acceptance, independent aileron droop and the remaining cockpit system displays remain unfinished.

The aileron-dance variant uses six custom visual outputs with source-based 2.5x differential travel and a 350 ms middle-panel delay in the air. It requires the separate FlyWithLua visual driver: see INSTALL_AILERON_VISUALS.txt when present. These animations do not enable or change the flight-control law; no arbitrary oscillation, full normal law, load alleviation or independent hydraulics are implemented.

The optional FlyWithLua control-law script starts disabled. The former native-EFIS, flyPad, and stock-guidance FCU Lua windows are source-only and are not packaged. The physical FCU selected-value controls remain a transitional simulator-I/O surface until the FBW flight-guidance computers are translated. See build-manifest.json and the licenses directory for build provenance.
